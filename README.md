# surflist

A directory for surf trips, in four categories, plus a blog:

- **Surf schools** — `/surf-schools/`
- **Surf shops** — `/surf-shops/`
- **Places to stay** (camps, hostels, eco-pods, campervans) — `/surf-stays/`
- **Surf services** (board repair, etc.) — `/surf-services/`
- **Blog** — `/blog/` (guides; one page per article at `/blog/<slug>/`)

The canonical hub for every place is its geographic page — country → region →
town (`/england/cornwall/newquay/`) — with a browse-all page per category and a
dedicated page for **every surf school** (e.g.
`/surf-schools/cornish-wave-surf-school/`) carrying schema.org markup for SEO and
LLMs. `verified` is a paid badge, not the gate for having a school page. Shops,
stays and services still show as cards that link out unless they are verified.

Everything is generated as plain, pre-rendered HTML with a self-hosted font — no
frameworks, no client-side rendering, no layout shift.

## Adding or editing content

See **[CONTRIBUTING.md](CONTRIBUTING.md)** for the full guide: the build
workflow, how to add listings (free and verified), how towns/regions/countries
and flags work, the verification standard, and how content reaches the homepage
and hub pages. See **[WORKFLOW.md](WORKFLOW.md)** for how the site is maintained
day to day (chat researches and curates; Claude Code implements via PR), and
**[CLAUDE.md](CLAUDE.md)** for Claude Code's operating rules.

The short version: edit a file in `data/`, run `node build.js`, then commit the
source **and** the regenerated files together. Never hand-edit the generated
HTML — the build overwrites it.

## Build

After any edit, run:

```bash
node build.js
```

It regenerates the homepage, every hub, every surf-school listing page (and any
verified pages in other categories), the blog index and article pages, plus
`sitemap.xml`, `robots.txt`, `llms.txt` and `/blog/feed.xml`. There's also an
integrity check that prints the place tree, flags thin towns, and fails on
place-slug, listing-slug or blog-slug collisions, missing country ISO codes, or
missing flag files:

```bash
node build.js --check
```

No dependencies — just Node. (Update `SITE` at the top of `build.js` if the
domain isn't `surflist.co`.)

## Add a whole new category later

Two steps, no other code changes:

1. Create `data/<name>.js` with `window.LISTINGS = [ ... ]`.
2. Add one entry to the `CATEGORIES` array at the top of `build.js` — its URL
   slug, titles, nav label, which data file, its facet field/label, and the
   schema.org type to use.

The hub, nav, sitemap and `llms.txt` all pick it up automatically.

## Preview locally

Because pages use clean directory URLs, preview with a server rather than opening
files directly:

```bash
node build.js
python3 -m http.server 8000     # then visit http://localhost:8000
```

## Deploy (Cloudflare Pages, via Git)

The repo is connected to Cloudflare Pages with:

- **Build command:** `node build.js`
- **Build output directory:** `/`

Every push rebuilds and republishes. Edit a file in `data/`, commit, push. Don't
commit hand-edits to the generated files — the build overwrites them.
