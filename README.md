# surflist

A surf-school directory. Pick a country, then a region, and the matching
listings show underneath. Free listings are rendered in the browser from a
single data file; **verified** listings additionally get their own static,
SEO/GEO-optimised page with schema.org markup.

```
index.html     the directory page (filter + card grid)
listings.js    your listings — THIS is the file you edit day to day
styles.css     all styling (shared by the index and the verified pages)
shared.js      tiny helper (URL slugs + country codes), used by page and build
build.js       generates the verified pages, sitemap.xml, robots.txt
favicon.svg    the little wave icon

# generated by `node build.js` (don't edit by hand):
schools/<slug>/index.html   one page per verified listing
sitemap.xml
robots.txt
```

## How the two tiers work

- **Free listing** — shows as a card on the homepage, rendered from `listings.js`
  in the browser. Its card links straight out to the school's own website. No
  page of its own.
- **Verified listing** (`verified: true`) — same card, but pinned to the top with
  a **Surflist verified** tag, and its card links to a **real static page** at
  `/schools/<slug>/`. That page is plain server-rendered HTML with meta tags,
  Open Graph, and a `SportsActivityLocation` JSON-LD block — the kind of page
  search engines rank and LLMs cite. The page then links out to the school.

## Add or edit a listing

Open `listings.js`, copy a block, change the details:

```js
{
  name: "Your Surf School",
  country: "Portugal",          // becomes a country button
  region: "Algarve",            // becomes a region button under that country
  town: "Sagres",
  url: "https://theirsite.com",
  levels: ["Beginner", "Intermediate"],   // Beginner, Intermediate, Advanced, Kids
  blurb: "One friendly line about them.",
  image: "https://.../photo.jpg",          // leave "" for an auto placeholder
  verified: false,                          // true = verified tag + own page
  socials: {                                // only the ones you fill in show
    instagram: "https://instagram.com/them",
  },

  // Only needed on VERIFIED listings (they power the page + schema):
  description: "A fuller paragraph shown on the listing's own page.",
  streetAddress: "1 Beach Road",
  lat: 37.0086,
  lng: -8.9407,
  priceRange: "€€",
},
```

The country/region buttons, images, verified pinning, and socials all update
themselves from the data. If two verified listings would share a URL slug, add a
`slug: "custom-slug"` field to one of them.

## Build the verified pages

Whenever you add or change a **verified** listing, regenerate its page:

```bash
node build.js
```

This (re)creates `schools/<slug>/index.html` for every verified listing, and
rewrites `sitemap.xml` and `robots.txt`. Free-only changes don't strictly need a
build, but running it is always safe. It has no dependencies — just Node.

> Update `SITE` at the top of `build.js` if your domain isn't `https://surflist.co`.

## Preview locally

You can now just **double-click `index.html`** — the homepage loads with full
styling and all the cards.

To also click through to the **verified pages**, run a tiny local server (their
URLs are clean directory paths like the live site, which `file://` can't follow):

```bash
cd surflist-pages
node build.js
python3 -m http.server 8000
# then visit http://localhost:8000  (verified pages at /schools/<slug>/)
```

## Deploy to Cloudflare Pages

**Option A — drag and drop (fastest)**
1. Run `node build.js` locally first (so the verified pages are up to date).
2. Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Upload assets**.
3. Name it `surflist`, drag in the `surflist-pages` folder, **Deploy**.
4. To update later: edit `listings.js`, run `node build.js`, upload again.

**Option B — connect a Git repo (auto-builds on every push)**
1. Push this folder to a GitHub/GitLab repo.
2. Cloudflare dashboard → **Pages** → **Connect to Git**, pick the repo.
3. Set **Build command** to `node build.js` and **Build output directory** to `/`.
4. Now every commit rebuilds the verified pages and publishes automatically —
   no local build needed.

## Point surflist.co at it

Pages project → **Custom domains** → **Set up a domain** → `surflist.co`.
If the domain's DNS is already on Cloudflare it's wired up automatically with a
free SSL certificate.

## Where to go next (only if you want to)

- **Search box:** the data's already in the page — a text filter is ~15 lines.
- **Free listings with pages too:** `build.js` could generate a lighter page for
  every listing, not just verified ones — verified would keep the richer schema.
- **Spreadsheet editing:** if hand-editing `listings.js` gets old, `listings.js`
  can be generated from Airtable or a Google Sheet at build time without changing
  anything else.
