# surflist

A directory for surf trips, in four categories:

- **Surf schools** — `/surf-schools/`
- **Surf shops** — `/surf-shops/`
- **Places to stay** (camps, hostels, eco-pods, campervans) — `/surf-stays/`
- **Surf services** (board repair, etc.) — `/surf-services/`

The homepage (`/`) is a hub that links to each section and features a few
listings from each. Free listings show as cards that link out to the business;
**verified** listings also get their own page (e.g.
`/surf-schools/newquay-surf-school/`) with schema.org markup for SEO and LLMs.

Everything is generated as plain, pre-rendered HTML with a self-hosted font — no
frameworks, no client-side rendering, no layout shift.


## Add or edit a listing

Open the file for that category in `data/`, copy a block, change the details:

```js
{
  name: "Your Business",
  country: "United Kingdom",   // becomes a country filter
  region: "Cornwall",          // becomes a region filter
  town: "Newquay",
  url: "https://theirsite.com",
  blurb: "One friendly line.",
  image: "",                   // "" = auto placeholder, or a photo URL
  verified: false,             // true = badge + own page (see below)
  socials: { instagram: "https://instagram.com/them" },

  // ...plus ONE category-specific field:
  //   schools:  levels: ["Beginner","Intermediate","Advanced","Kids"]
  //   shops:    offerings: ["Board rental","Ding repair","Wetsuits", ...]
  //   stays:    stayType: "Camp"        (Camp | Hostel | Eco-pod | Campervan)
  //   services: serviceType: "Board repair"
}
```

That category-specific field becomes both the tags on the card and a filter in
the sidebar. Country and region filters build themselves from the data.

### Verified listings

Set `verified: true` and add these fields - they power the listing's own page
and its schema:

```js
description: "A fuller paragraph shown on the page.",
streetAddress: "1 Beach Road",
lat: 50.4165,
lng: -5.1004,
priceRange: "££",
```

Free listings don't need them. If two verified listings in the same category
would share a URL slug, add `slug: "custom-slug"` to one.

## Build

After any edit, run:

```bash
node build.js
```

It regenerates the hub, every category page, every verified page, plus
`sitemap.xml`, `robots.txt`, `llms.txt` and `_redirects`. No dependencies - just
Node. (Update `SITE` at the top of `build.js` if your domain isn't
`surflist.co`.)

## Add a whole new category later

Two steps, no other code changes:

1. Create `data/<name>.js` with `window.LISTINGS = [ ... ]`.
2. Add one entry to the `CATEGORIES` array at the top of `build.js` - its URL
   slug, titles, nav label, which data file, its facet field/label, and the
   schema.org type to use.

The hub, nav, sitemap, and `llms.txt` all pick it up automatically.

## Preview locally

Because pages use clean directory URLs (like the live site), preview with a
server rather than opening files directly:

```bash
node build.js
python3 -m http.server 8000     # then visit http://localhost:8000
```

## Deploy (Cloudflare Pages, via Git)

The repo is connected to Cloudflare Pages with:

- **Build command:** `node build.js`
- **Build output directory:** `/`

So every push rebuilds and republishes. Just edit a file in `data/`, commit,
push. Don't commit hand-edits to the generated files - the build overwrites them.

### Old URLs

Schools used to live at `/schools/<slug>/`. `build.js` writes a `_redirects`
file that 301s those to the new `/surf-schools/<slug>/`, so any old links keep
working.
